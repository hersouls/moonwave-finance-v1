## 영역별 상세

### layout
The layout shell is one of the most design-system-disciplined areas in the app: it consistently uses semantic tokens (text-heading/sub/disabled, bg-surface-*, border-base, var(--hover-bg)), the primary/accent scale, fluid type (text-h2-fluid, text-body3), token-backed elevation (el-*, elevation-1..4), z-index vars, and custom utility aliases (nav-header, nav-bottom, touch-target-icon) that already enforce 44px touch targets and safe-area insets (pt-safe-only/pb-safe). Hardcoded violations are few and mostly low/medium: a raw bg-black/50 scrim in MobileNav, a couple of arbitrary fractional-shadow / blob values, and a dark:-conditional hover color that could use semantics. The biggest gaps are responsive/feature, not token, related: the canonical mobile|PC split is hard-coded to lg(768px) which leaves the 600-767 tablet/Z-Fold-open band rendering the phone bottom-nav with a desktop-less layout, the desktop chrome offers no keyboard shortcut surface beyond Cmd+K/undo, and there is no command palette, density toggle, or master-detail affordance that a financial power-user expects at >=1024px. Mobile lacks gesture nav (swipe-to-open drawer, swipe-between-segments), pull-to-refresh, and a sticky thumb-reachable primary CTA.

### ui-primitives
The UI primitives are largely well-tokenized: most use Foundation CSS component classes (badge-*, btn-*, toast-*, card-base, el-*, elevation-*) and semantic text/surface tokens, with disciplined dynamic-only inline styles (spotlight %, pull progress, masked reveal). The main violations are concentrated in a few files: HeroMetricCard hardcodes emerald/red Tailwind palette classes for trend deltas (should be value-positive/negative tokens), ErrorBoundary uses text-red-500 on a danger surface, EmptyState ships a full arbitrary text-lg/xl/2xl + text-base size map instead of the KT typography scale, and Sparkline/SuccessAnimation default to raw #10b981/#ef4444 hex instead of chart/viz CSS vars. Responsively the primitives are solid (Dialog is a proper mobile-sheet/desktop-modal split, IconButton enforces 44px targets, FAB respects safe-area), but EmptyState, Tabs, Tooltip and Select have small-width/touch-target gaps, and Tooltip is hover/focus-only with no mobile or viewport-edge handling. There is strong room for high-end mobile (bottom-sheet Select, swipe-to-dismiss is partially there) and desktop-expert (sortable a11y tables, command palette, hover previews) enhancements layered on these primitives.
